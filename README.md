# PromptLint

站在**模型视角**诊断提示词：找出那些会让 AI 助手产生歧义、偏差或误解的部分，并给出它更希望收到的结构化写法。

不是"提示词优化器"（不替你改写意图），而是**歧义体检仪**——告诉你模型会在哪一步猜错、为什么猜错、以及怎么把话说清楚。

```
$ python -m prompt_lint.cli "麻烦你帮我把这篇文章优化一下，写得好看点、高级一点，另外顺便帮我起个标题，尽量简洁全面，不要太多专业术语，谢谢！"

  PromptLint 诊断结果   得分 28/100    评级 F
  模型收到的有效信息太少，产出随机

[高危] 主观不可执行形容词   (-18 分)
     命中：「好看点」、「高级」
     模型视角：'好看''高级感'不是可验证标准。模型会套用它见过的高频模板来近似
               这些词，产出的是通用风格的平均值，而不是你脑子里那个样子。
     怎么改：把审美判断翻译成可检查的特征，或直接给一个样板。
...
### 重写后的提示词（RCFT 结构）
# 角色 / # 背景与目标 / # 输入材料 / # 任务 / # 输出格式与长度 / # 约束 / # 示例
## 动手前先回答（按优先级）
1. 「好看点、高级」能拆成哪几个可检查的特征？
2. 请把「这篇文章」的原文完整粘贴进提示词，模型看不到你本地的文件。
```

## 快速开始

```bash
git clone https://github.com/<你的用户名>/prompt-lint.git
cd prompt-lint
pip install -e .

# 直接分析一段文本
python -m prompt_lint.cli "帮我优化一下这个方案"

# 从文件读，并导出 Markdown 报告
python -m prompt_lint.cli -f my_prompt.txt --md report.md

# 只要重写后的提示词（可直接粘回对话框）
python -m prompt_lint.cli -f my_prompt.txt --rewrite-only

# 机器可读输出，方便接进流水线
python -m prompt_lint.cli --json "帮我总结这份报告"
```

退出码：`0` 表示得分 ≥ 75，否则为 `1`——可以直接挂进 CI 或 pre-commit。

在线版：推到 GitHub 后开启 **Settings → Pages → GitHub Actions**，CI 会自动部署 `web/`，得到一个可分享的静态网址。

## 诊断什么

16 个检测器，归入 5 个维度。每一条都回答三个问题：**命中了什么 → 模型为什么会误解 → 怎么改**。

| 维度 | 检测器 | 级别 |
|---|---|---|
| 语义清晰度 | 口语化冗余与客套、礼貌用语占位、模糊指代、模糊限定词、主观不可执行形容词 | 高/中/轻 |
| 任务定义 | 动作动词模糊、缺少明确任务动词、多任务混杂 | 高/中 |
| 上下文供给 | 缺少背景与受众、引用了未提供的材料、未指定角色视角 | 高/中 |
| 输出约束 | 未指定输出格式、未定义长度边界、否定式指令、约束自相矛盾 | 高/中/轻 |
| 结构组织 | 无结构长段落 | 轻 |

几条判断标准比较硬，值得单独说明：

- **否定式指令要扣分。** 模型对"不要做 X"的执行力明显弱于"只做 Y"——注意力机制会把 X 这个概念激活，结果反而更容易出现 X。所以工具会提示你翻成正面的"只允许……"。
- **"引用了未提供的材料"是高危。** 你说"帮我把这篇文章改一下"但没给文章，模型不会说"我没看到"，它会直接编一份然后作答。这是幻觉最高发的场景之一。
- **"下面/这个"出现在开头会升级为高危。** 说明指代对象从未在前文出现过，模型只能猜一个最像的。
- **主观形容词按高危算。** "高级感"不可验证，模型只能用训练分布里的平均值去近似。

## 输出什么

1. **总分与评级**（A/B/C/D/F）+ 一句话结论
2. **问题清单**：每条含命中片段、模型视角解读、改写建议
3. **重写后的提示词**：RCFT 结构（Role 角色 / Context 背景 / Task 任务 / Format 格式），
   能提取的信息直接搬过去，缺的给占位符和引导问题，不会让你重写一遍
4. **已清理的噪声**：列出被删掉的口语冗余，让你看到自己说了多少废话
5. **动手前先回答**：按优先级列出 3-6 个问题——这几个问题不回答，模型就只能猜

## 架构：一份规则表，两个运行时

```
prompt_lint/rules.json      ← 唯一真相源：词表、权重、模型视角文案、重写模板
        │
        ├── prompt_lint/analyzer.py   Python 引擎（CLI / 可 import / 可接流水线）
        │   └── prompt_lint/rewrite.py
        │
        └── web/app.js                浏览器引擎（读同一份 JSON，纯前端计算）
```

改规则只需要改 `rules.json` 一处。测试 `tests/test_parity.py` 会用同一批样例分别跑
Python 和 Node，断言两端的分数与问题清单**完全一致**——不一致就 CI 失败。

前端不做任何网络上报，提示词不出浏览器。

```
prompt-lint/
├── prompt_lint/
│   ├── rules.json      规则表（唯一真相源）
│   ├── analyzer.py     检测 + 评分
│   ├── rewrite.py      RCFT 结构化重写
│   └── cli.py          命令行
├── web/                GitHub Pages 静态站点（无构建、无依赖、无后端）
├── tests/              29 个用例，含双端一致性校验
└── .github/workflows/  测试 + 部署 Pages
```

## 形态选型：为什么是"Python 引擎 + 静态站点"

需求是把工具做成能进代码仓库、托管在 GitHub 的形态。五种候选的对比：

| 形态 | 进仓库 | 托管成本 | 可测试性 | 迭代速度 | 结论 |
|---|---|---|---|---|---|
| **Python 脚本 + 静态站点** | ✅ 纯文本，diff 清晰 | ✅ Pages 免费，push 即部署 | ✅ pytest + CI + 双端一致性 | ✅ 改 JSON 即改规则 | **推荐** |
| 纯前端单文件 HTML | ✅ | ✅ 可直接扔 Pages | ⚠️ 逻辑塞在 HTML 里难测 | ✅ | 次选，适合只要一个页面的场景 |
| 网站（带后端） | ✅ | ❌ 要服务器、要域名备案 | ✅ | ⚠️ 多一层部署 | 没必要，本工具无状态、无用户体系 |
| 小程序 | ✅ | ❌ 要注册、备案、平台审核 | ⚠️ | ❌ 每次发版要审核 | 否决，审核成本远大于收益 |
| 桌面 / 移动应用 | ✅ | ❌ 打包签名分发 | ⚠️ | ❌ 最慢 | 否决，纯文本处理不需要原生壳 |

选它的三条硬理由：

1. **工具的价值在规则，不在界面。** 规则表是纯 JSON，进 Git 后每次改动都是可读的 diff，
   能 code review、能回滚、能开 PR 讨论某条规则是否该算高危。做成 Electron 或小程序，
   规则就埋进了二进制或平台审核流程里。
2. **零边际成本地拿到两个入口。** 同一份规则表，CLI 给工程师接流水线（退出码可挂 CI），
   静态页给非技术同事直接用。写完一次，两种人都能用。
3. **隐私是这个品类的刚需。** 用户要粘的是真实的工作提示词，里面可能有未公开的方案、
   合同条款、代码。纯前端计算意味着没有任何数据上传，这一点本身就是卖点。

## 自定义规则

```bash
python -m prompt_lint.cli --rules my_rules.json "待检测的提示词"
```

`rules.json` 里每个检测器支持 6 种 `kind`：

| kind | 行为 | 关键字段 |
|---|---|---|
| `keyword` | 命中词表即扣分 | `keywords`、`boost_if_early` |
| `regex` | 正则匹配 | `patterns` |
| `absence` | 词表一个都没出现才扣分 | `keywords`、`regex_positive` |
| `counter` | 命中数达到阈值才扣分 | `keywords`、`threshold`、`count_mode` |
| `conflict` | 词对同时出现 | `pairs` |
| `structure` | 未分段且超长 | `min_length` |

调权重改 `scoring.severity_weight`，调评级线改 `scoring.grades`。改完跑 `pytest tests/` 确认没打破双端一致。

## 已知边界

- **规则法，不是语义理解。** 能稳定抓"模式化"的歧义（指代、模糊限定、缺格式），
  抓不住"意图本身有问题"。比如"帮我写个方案"会被判缺上下文，但工具无法替你想出该是什么方案。
- **中文为主。** 词表按中文口语习惯调过，英文提示词覆盖率明显更低。
- **不含 LLM 评判。** 纯规则意味着确定性、零成本、可离线，但也意味着上限。
  下一步可选：加一个 `--llm` 开关，把规则初筛结果交给模型做二次判断。
